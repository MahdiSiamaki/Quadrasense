# RAR fixtures

Small RAR 5 archives of **synthetic** files, read by `ImportArrivalsTests`. They are committed
because nothing in the .NET runtime, and no free tool, writes RAR: they were packed once, on
2026-11-11, with `Rar.exe` from WinRAR 7. ZIP and gzip fixtures are made by the tests themselves.

Nothing in them is real. The numbers are the made-up ones the test suite already uses
(`9120000001`, `432110000000001`, `35004012000001`) counted upwards.

| Archive | Holds | Made with |
|---|---|---|
| `DeviceDatabaseTAC09Nov2026.rar` | `DeviceDatabase.csv` - the shape GSMA delivers: the date is on the archive, not on the file | `rar a -ma5 -m3` |
| `two-days-solid.rar` | `daily_subs_device_sim_info_2026-10-17.csv`, `…-18.csv`, as one solid stream | `rar a -ma5 -m3 -s` |
| `mixed.rar` | `readme.txt`, `data/DeviceDatabase.csv`, `__MACOSX/._DeviceDatabase.csv`, an empty `empty.csv`, and `packed.csv`, which is a ZIP | `rar a -ma5 -m3` |
| `password.rar` | `DeviceDatabase.csv`, data encrypted (password `Secret1`) | `rar a -ma5 -m3 -pSecret1` |
| `password-names.rar` | the same, file names encrypted too | `rar a -ma5 -m3 -hpSecret1` |
| `split.part1.rar` | the first 64 KB volume of a four-volume archive of `noise.csv` | `rar a -ma5 -m0 -v64k` |

The files inside are generated by formula, and the tests regenerate them from the same formulas
and compare SHA-256, so an archive and its expectation cannot drift apart unnoticed:

|---|---|---|
| `DeviceDatabase.csv` | 2,188 | `14144a3060817b98b8a9778ca1866ae3b007002e0b23681305c1139e114e0cb7` |
| `daily_subs_device_sim_info_2026-10-17.csv` | 2,372 | `bb666e8d6c96c216649b4945c2dd31f60b01ac45a96c0f77aa5b06d69a6ecf23` |
| `daily_subs_device_sim_info_2026-10-18.csv` | 1,906 | `a8ab17e4db2dace05bbb7fa5ecd7dc8090d7d0656099f33a925ceba8502f31f6` |

**Not covered: RAR 4.** WinRAR 7 no longer writes it, and no RAR 4 archive was to hand. The reader
(SharpCompress) supports it; this suite does not prove it.
